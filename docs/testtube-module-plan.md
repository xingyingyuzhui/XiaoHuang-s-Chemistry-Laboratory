# 小黄的化学实验室 · 「试管」虚拟实验模块方案

> **状态**：规划完成，尚未进入实现。  
> **定位**：与「计算」「电子排布」同级的顶层功能，不隶属于「课堂」。  
> **首期目标**：用可控、可验证、可扩展的本地虚拟实验，替代“只看实验脚本”的被动预习体验；不追求通用化学仿真器，也不让 AI 决定化学事实。

---

## 1. 产品需求与边界

### 1.1 入口与产品关系

顶部导航调整为：

```text
元素周期表｜3D 分子｜计算｜电子排布｜试管｜元素乱斗｜课堂
```

- **试管**：独立的交互式虚拟实验台，可自由探索、完成任务、回看记录。
- **课堂 → 实验探究**：保留既有实验脚本、预习、编辑、导入导出能力；未来可通过 `testtubeScenarioId` 跳转到对应的试管实验。
- **不做账号/云同步**：首期所有内置内容随安装包提供；个人实验记录仅保存本机。

### 1.2 用户可完成的事

1. 从试剂架选择受支持的试剂、器材和操作；
2. 将试剂加入试管，执行滴加、加热、搅拌、静置、倾倒等操作；
3. 看到由实验条件驱动的现象：颜色、沉淀、气泡、固体消失、温度提示等；
4. 在任务实验中按要求完成目标，并获得过程反馈；
5. 回看本次操作、现象和满足条件后出现的化学方程式；
6. 在需要时请求 AI 用通俗语言解释“为什么发生/为什么没有发生”，但化学判定始终来自内置规则。

### 1.3 明确不做的事

- 不做任意试剂自由组合的“万能反应引擎”；
- 不做真实流体动力学、连续粒子物理或高成本的全 3D 场景；
- 不由 AI 生成、确认或修改反应条件、产物和安全结论；
- 首期不做多人协作、教师远程监控或云端账户。

这些边界保证实验结果可追溯、课堂使用可控，也避免性能和化学正确性失控。

## 2. 首期体验与界面规划

### 2.1 二级页面

```text
探索台｜任务实验｜实验记录
```

| 页面 | 用途 | 首期范围 |
| --- | --- | --- |
| 探索台 | 自由尝试少量已支持操作 | P1 提供单一场景和受限试剂架 |
| 任务实验 | 根据目标完成规定实验 | P2 起提供场景卡、目标和判定 |
| 实验记录 | 回放操作、查看现象与方程式 | P3 起保存本机记录 |

### 2.2 实验台布局

```text
┌──────── 试剂与器材 ────────┬────────────── 实验台 ──────────────┬──── 观察与记录 ────┐
│ 试剂架 / 器材架            │ 试管、试管架、滴管、酒精灯          │ 当前现象             │
│ 可用操作与数量              │ 点击/拖放后按步骤执行                │ 方程式（条件满足后）  │
│ 安全提醒                    │ 视觉反馈：液面、气泡、沉淀、颜色      │ 安全与操作日志        │
└───────────────────────────┴──────────────────────────────────┴──────────────────────┘
```

视觉基调应延续现有“手绘实验室”风格：清晰优先于拟真；所有颜色变化必须同时提供文字说明，操作不能只依赖拖放。

### 2.3 最小可用场景（P1）

**碳酸钙与稀盐酸反应**：

- 器材：试管、滴管、碳酸钙固体、稀盐酸；
- 操作：选择固体 → 加入试管 → 选择盐酸 → 滴加；
- 触发条件：试管中已有碳酸钙，且滴加的是足量稀盐酸；
- 现象：白色固体逐步减少，产生连续气泡；
- 记录：`CaCO₃ + 2HCl → CaCl₂ + H₂O + CO₂↑`，并提示气体检验属于后续步骤；
- 反例：空试管滴酸、只放固体、不支持的试剂，均只记录操作，不虚构反应。

## 3. 化学内容与规则设计

### 3.1 受控场景数据，而非通用规则

每个内置场景用可审阅的数据表达“允许什么、发生什么、如何显示”，例如：

```js
{
  id: 'caco3-hcl-v1',
  title: '碳酸钙与稀盐酸',
  initialState: { vessels: { tube1: { contents: [] } } },
  inventory: ['calcium-carbonate', 'dilute-hydrochloric-acid'],
  rules: [{
    id: 'carbonate-acid',
    when: { vessel: 'tube1', contains: ['calcium-carbonate', 'dilute-hydrochloric-acid'] },
    result: {
      phenomena: ['bubbles', 'solid-dissolving'],
      equation: 'CaCO₃ + 2HCl → CaCl₂ + H₂O + CO₂↑',
      safety: ['按规范佩戴护目镜；酸液不可直接接触皮肤。']
    }
  }]
}
```

规则数据须明确：反应物、必要条件、产物/现象、教学说明、方程式、安全提示、版本号。内置规则的科学审核应在数据提交时完成，不放到运行时交给模型猜测。

### 3.2 纯状态引擎

使用纯函数处理所有操作：

```text
state + action -> nextState + events
```

- `action`：`select`、`addSolid`、`drop`、`heat`、`stir`、`wait`、`reset`；
- `nextState`：容器内容、温度状态、可见现象、已解锁信息、操作日志；
- `events`：视觉/音效提示，如 `bubbles-start`、`solid-dissolve`；
- 渲染层只消费状态和事件，不能自行决定“是否反应”。

这使同一操作序列可复现、可测试、可回放，也便于未来新增新试剂和多步骤实验。

### 3.3 后续场景优先级

| 批次 | 场景 | 重点知识 |
| --- | --- | --- |
| P1 | 碳酸钙 + 稀盐酸 | 气体生成、固体消失、反应条件 |
| P2 | 硫酸铜 + 镁 | 金属活动性、置换反应、溶液颜色变化 |
| P2 | 酸碱滴定（受限步骤） | 指示剂变色、滴定终点、操作顺序 |
| P3 | 过氧化氢分解 | 催化剂、气泡、变量控制 |
| P3 | 铁与硫酸铜 | 置换、质量变化、证据链 |

每增加一个场景，都必须增加“正确路径、错误/不触发路径、重放一致性”测试。

## 4. 技术方案与工程约束

### 4.1 与现有工程的接入点

| 层级 | 现有责任 | 试管模块做法 |
| --- | --- | --- |
| 顶层切换 | `index.html` → `src/main.js` | 增加 `data-tab="testtube"` 与 `panel-testtube`；接入既有 `createFeatureLoader`，不另建 Tab 控制器 |
| 前端行为 | `src/` 按功能分模块 | 新建 `src/testtube/`，数据、规则、UI、渲染、生命周期分离 |
| 样式 | `src/styles/index.css` 聚合 | 新建 `src/styles/_testtube.css`，不将大段样式放回全局文件 |
| 后端/数据 | Express + sql.js | P0/P1 不新增 API、不开 SQLite 表；P3 才存本机实验记录 |
| 课堂联动 | `src/ai-classroom/` | P3 通过稳定的 `scenarioId` 跳转，不反向耦合试管 UI |

### 4.2 推荐目录

```text
src/testtube/
  index.js                 # init / activate / deactivate / destroy，对接主入口
  engine.js                # 纯 reducer：state + action -> state + events
  scenario-registry.js     # 内置场景索引和版本
  data/
    caco3-hcl.js           # 一个场景一份可审核数据
  actions.js               # UI 操作转成受控 action
  view-model.js            # 将 engine state 转为展示模型
  shell.js                 # DOM 控制器、可访问性、事件绑定
  renderer/
    stage.js               # Pixi 场景创建与销毁
    vessel.js              # 试管/液面/沉淀渲染
    effects.js             # 气泡、颜色、轻量提示效果
  templates.js             # 静态 HTML 模板

src/styles/_testtube.css
test/testtube-engine.test.cjs
test/testtube-lifecycle.test.cjs
```

### 4.3 渲染技术选型

- **主渲染：PixiJS v8**（需作为运行时依赖新增）：用于 2D 试管、液体遮罩、气泡、沉淀、拖拽反馈和轻量动画；仅在进入“试管”页动态导入。
- **现有 Three.js**：保留给 3D 分子；未来若确有价值，可用在局部“微观观察”，不能让整个试管台依赖 3D。
- **浏览器 DOM/CSS**：承载面板、按钮、可访问性文字、操作记录和方程式，不能把关键说明画死在 Canvas 内。
- **音效**：后续以短促、可关闭的 Web Audio/本地音频实现；默认不自动播放背景音。

### 4.4 生命周期与性能规则

- `src/main.js` 必须只在首次打开试管页时动态导入模块；首屏不能静态导入 PixiJS；
- 同时只能存在一个 Pixi 应用实例和一个 ticker；离开页面时停止 ticker、取消动画、释放事件监听；
- 展示效果由 `events` 驱动；不得用循环定时器自行改变化学状态；
- 限制同屏粒子数量、限制设备像素比，优先使用矢量/纹理复用；
- 先以 CSS/遮罩模拟液面和气泡，不引入流体模拟、物理引擎或 Worker；只有测得卡顿后才评估 OffscreenCanvas。

### 4.5 AI 的正确职责

AI 是**解释层**，不是**规则层**：

- 可做：解释本次操作与现象、追问变量控制、生成实验报告初稿、说明未触发原因；
- 不可做：判断反应是否发生、补全未知产物、替换内置安全结论、在无规则时“生成一个看起来合理的现象”；
- 所有 AI 输出应标为“AI 辅助说明”，并能一键关闭/重试。

## 5. 数据与持久化准备

### 5.1 P0/P1：完全内置、无数据库写入

- 场景、试剂、规则、文字均放在 `src/testtube/data/`；
- 用户刷新或重置后回到场景初始状态；
- 不改动 `server/data/`，不把试验过程伪装成已保存的学习数据。

### 5.2 P3：本机实验记录

在确认记录体验有价值后，才由 API 写入本机 SQLite。建议表：

```text
testtube_runs
  id, scenario_id, scenario_version, mode,
  actions_json, final_state_json, summary_json,
  created_at, updated_at
```

- `actions_json` 是可回放的语义操作序列，不保存画布像素或动画帧；
- `scenario_version` 防止规则升级后旧记录被错误解释；
- 先定义导出 JSON 的版本化格式，再考虑“备课包”包含自定义任务；
- 涉及 DB schema 时：迁移可重复、路由校验输入、测试新增/读取/非法 payload，且不得覆盖用户数据。

## 6. 实施计划与交付物

### P0：架构落位与空壳（先做）

**目标**：新 Tab 可安全进入/离开，不影响任何已有 Tab，也不增加首屏负担。

1. 在导航和面板增加「试管」；
2. 建立 `src/testtube/`、`_testtube.css` 与 `init/activate/deactivate/destroy` 生命周期；
3. 使用既有 `createFeatureLoader` 动态加载模块；
4. 增加最小纯状态引擎、场景 registry 和空场景；
5. 实现 loading/error/空态，并适配键盘、焦点和窄窗口；
6. 加入生命周期测试：重复进入离开不重复注册监听、不残留 ticker、不影响其他面板。

**完成标准**：空壳体验完整；构建后首屏不含 Pixi chunk；现有测试和构建通过。

### P1：第一个可玩的受控实验（先做）

**目标**：完成“碳酸钙 + 稀盐酸”从操作、判定、动画到文字记录的闭环。

1. 接入 PixiJS 动态渲染试管、固体、滴管、液面与气泡；
2. 完成 `select/addSolid/drop/heat/stir/wait/reset` 语义 action；
3. 用纯规则引擎判定反应，只在条件满足时发出 `bubbles-start` / `solid-dissolve`；
4. 展示实时观察、操作日志、方程式和安全提示；
5. 加入可访问性替代操作：按钮可完成全部流程，画布现象有文字同步；
6. 写 engine 测试：正常触发、空试管不触发、错误材料不触发、重置、同序列重放一致；
7. 人工烟测：桌面和窄窗口、反复切换页面、刷新与重置。

**完成标准**：用户不看说明也能完成一次实验；规则结果稳定；退出页面后动画停止。

### P2：任务化与场景扩展

**目标**：把“能玩”变为“可用于学习”。

1. 添加任务实验页：实验目标、可选提示、完成判定、错误操作引导；
2. 新增 2 个经审核的场景（优先硫酸铜 + 镁、受限酸碱滴定）；
3. 引入场景 schema 校验，防止规则数据漏写现象/方程式/安全内容；
4. 添加“现象 → 证据 → 结论”三段式实验小结；
5. 从课堂实验脚本增加稳定的 `testtubeScenarioId`，实现单向跳转。

### P3：记录、复盘与课堂协作

**目标**：让实验过程可回看、可复习、可被课程引用。

1. 新增本机实验记录 API 与 SQLite 迁移；
2. 实现操作回放、结果摘要和 JSON 导出；
3. 课堂实验页可打开匹配的试管场景，并带回完成摘要；
4. AI 辅助解释与报告初稿（只读取确定的过程/结果）；
5. 将试管任务结果接入本机“知识掌握地图”的证据来源。

### P4：表现与内容制作能力

**目标**：达到精致、可持续扩展的体验，但不牺牲可维护性。

1. 微观观察模式（按需 Three.js）、液面遮罩/材质升级、原创建模资产；
2. 更丰富但可限制的器材操作，如过滤、气体检验、加热曲线；
3. 教师本机自定义任务模板与导入导出；
4. 基于真实性能数据，再评估 OffscreenCanvas、纹理图集或资源压缩；
5. 每个新实验做化学审阅、教学审阅、无障碍审阅和回归测试。

## 7. 测试、质量与验收清单

### 7.1 自动化测试

- 规则引擎是纯函数：无 DOM、无随机化学结果、无网络依赖；
- 每个场景：正确路径触发预期现象；错误路径不触发；重放结果一致；
- 场景 schema：id 唯一、必填教学/安全字段齐全、方程式展示字段合法；
- 生命周期：模块懒加载、`deactivate/destroy` 后不继续运行；
- P3 API：非法输入拒绝、记录按本机数据隔离、迁移可重复。

### 7.2 人工验收

- 从首屏打开试管后，加载状态清晰，无明显白屏或阻塞；
- 鼠标、触屏/拖放替代方案、键盘都能完成核心实验；
- 颜色变化、气泡等视觉现象同时有文本说明；
- 操作顺序改变时，现象和方程式不会提前出现；
- 在试管、3D 分子、电子排布之间反复切换，动画不会叠加、CPU 不持续占用；
- 每条方程式、条件和安全说明经过人工化学审校。

### 7.3 发布前检查

1. `npm test` 与 `npm run build` 通过；
2. 浏览器开发模式和 Electron 打包后的“试管”页都实测；
3. 检查动态 chunk：PixiJS 未进入首屏入口包；
4. 检查无障碍文本、键盘焦点、窄窗口和高对比度主题；
5. 不手改 `dist/`、`server/public/`、`.electron-stage/` 或 `server/data/`；按现有发布流程重新生成安装包。

## 9. 里程碑决策点

- **P1 验收后**再决定是否扩场景；不能因为画面好看而跳过规则与测试；
- **P2 验收后**再决定是否建设记录表和课堂联动；
- **P3 有真实使用价值后**再接 AI 和知识掌握地图；
- **P4 有性能数据后**再升级 3D、Worker 或复杂材质。

每一阶段均应独立提交、独立验证；不要在同一个提交里混入课堂、方程式、电子排布等无关改动。
